The idea in five scrolls

From one instruction to a storm of pixels

Everything below is real: the image, the order it was painted in, and which Streaming Multiprocessor (SM) painted each pixel all come from a Verilog simulation of kernel 15_mandelbrot.psa.

01

One thread, one pixel

A pixel shader is a tiny program that decides one pixel's color. A GPU runs it as a thread: its own registers, its own coordinates, the same code as everyone else.

02

Eight threads, one instruction

Fetching and decoding an instruction is expensive, so the GPU does it once for a warp of threads and feeds 8 lanes (32 on NVIDIA hardware) in lockstep. Same instruction, different data.

03

512 threads, two SMs

The 32 × 16 image is one launch: 16 blocks of 32 threads, each block split into 4 warps. The dispatcher hands blocks to whichever SM is free. Blue rows ran on SM 0, violet on SM 1.

04

The storm

Scroll and the image paints itself in the exact order the Verilog wrote each pixel to memory. Both SMs work at once, block by block, 23,420 clock cycles in total.

05

When lockstep breaks

Each Mandelbrot pixel needs a different number of iterations, and a warp waits for its slowest lane. Magenta shows idle lanes: the cost of divergence, and the first thing GPU programmers learn to design around.

      Run the real thing
      
Your machine, the actual Verilog

      
On Ubuntu or Windows through WSL2 (Windows Subsystem for Linux), five commands take you from nothing to a waveform of the Mandelbrot kernel. Every figure in the course is regenerated from your own simulation.

      View on GitHub →
    

    

      
bash


git clone https://github.com/Normansrule/pixelstorm-gpu.git
cd pixelstorm-gpu
bash scripts/setup_ubuntu.sh      # Icarus Verilog, Verilator, GTKWave, Node.js
./pixelstorm test                 # RTL == golden model, every kernel
./pixelstorm rtl mandelbrot --vcd  # the fractal, as a waveform
make serve                        # this site at localhost:8000
