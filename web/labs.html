1Memory coalescing

Every lane of a warp asks for one word at base + lane × stride + offset. DRAM only delivers whole lines, so the load/store unit groups lanes by line. Fewer lines means fewer transactions and less wasted bandwidth.

In the real world: Nsight Compute reports this as "sectors per request". The ideal for 32 lanes reading 4-byte values is 4. See docs/08 and run 08 coalescing in the visualizer.

2Shared-memory bank conflicts

Shared memory is sliced into banks; word a lives in bank a mod banks. Each bank serves one word per cycle. Lanes that hit the same bank at different words must take turns. Lanes reading the same word share it for free.

In the real world: this is why CUDA tiles are declared __shared__ float tile[32][33]. The extra column is padding. See docs/08 and 09 bank conflicts.

3Branch divergence

A warp has one instruction stream. When lanes disagree on if (cond) {A} else {B}, the warp runs A with some lanes switched off, then B with the others. Predication runs both for every lane without a branch.

In the real world: Nsight Compute's "warp execution efficiency" is the SIMD efficiency shown here. Compilers pick predication for short bodies. See docs/07 and 03 divergence.

4Latency hiding with more warps

Each warp repeats: one load, then some arithmetic that needs the loaded value. While a warp waits for memory, a latency-hiding scheduler issues from another warp. Pixelstorm today does not; this lab shows what exercise 2 in docs/12 would buy.

In the real world: an H100 SM holds up to 64 warps precisely so that hundreds of cycles of DRAM latency can be covered by other warps' work. Rule of thumb: warps needed ≈ latency ÷ arithmetic per load + 1.

5Occupancy calculator

How many warps can live on one SM at once? Each resource (registers, shared memory, thread slots, block slots) sets a limit; the smallest one wins. More resident warps means more latency hiding (lab 4).

Simplified from NVIDIA's occupancy rules (register allocation in 256-register units per warp; shared memory rounded to 1 KB). For exact numbers use the occupancy section of Nsight Compute. Limits per GPU are from NVIDIA's CUDA Programming Guide, "Compute Capabilities" table.

6Pixels and warps

A GPU shades an image with one thread per pixel, grouped into warps. Here every pixel of the Mandelbrot set needs a different number of iterations, and a warp runs as long as its slowest pixel. The right-hand image shows the cost: bright magenta pixels sat idle, waiting for a neighbour in the same warp. Change the warp shape and watch the waste move.

In the real world: GPUs shade pixels in 2 x 2 "quads" and pack quads into warps, because nearby pixels usually take similar paths. That spatial coherence is why tiled warps waste less. Run 15 mandelbrot in the visualizer to see the same effect in the Verilog.
